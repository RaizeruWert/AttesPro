# План и архитектура проекта «АттестПро»

## Сценарий пользователя

1. Педагог регистрирует один аккаунт.
2. Заполняет общий профиль.
3. Добавляет все свои должности и предметы как отдельные записи.
4. Создаёт отдельную подготовку к аттестации для нужной должности.
5. Заполняет анкету, загружает подтверждающие документы.
6. Система сравнивает загруженные файлы с настроенным чек-листом.
7. После устранения пропусков пользователь формирует ZIP-пакет.

## Пример совмещения

| Запись | Тип | Должность | Предмет |
|---|---|---|---|
| 1 | Руководящая | Заместитель директора | — |
| 2 | Педагогическая | Учитель | Молдавский язык |

Обе записи принадлежат одному `User`. Две заявки связаны с разными `Assignment`, а документы и анкеты хранятся внутри соответствующей заявки. Это предотвращает смешение управленческих и педагогических материалов.

## Сущности базы данных

- User — учётная запись.
- Profile — общие сведения человека.
- Assignment — одна должность / предметная нагрузка.
- AttestationApplication — отдельная процедура подготовки по одной должности.
- ChecklistItem — настраиваемый перечень материалов.
- EvidenceDocument — загруженный файл, связанный с конкретной заявкой.

## Следующие этапы развития

- Разделить анкету на независимые наборы вопросов для каждой категории должностей.
- Вынести требования и формы в версионируемые профили по актуальным редакциям нормативных актов.
- Добавить электронное формирование заявлений и титульных листов по официальным шаблонам.
- Добавить кабинет администратора организации с разграничением доступа.
- Добавить аудит действий, резервное копирование и объектное хранилище.
- Добавить автоматические интеграционные тесты и CI GitHub Actions.
